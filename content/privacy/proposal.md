> **적용 전 확인**  
> 이 문서는 첨부된 개인정보 처리방침 v1.1을 바탕으로 확장한 **개정 검토안**이다. 원문의 기간은 아래에 출처를 표시해 유지했으며, 보완·변경 제안은 별도로 설명한다. 담당 연락처, 실제 수집 항목, 서비스 운영 주체, 수탁자·국외이전·CCTV 현황을 확정하기 전에는 완료된 운영 방침으로 표시하거나 이 문서만으로 동의를 받아서는 안 된다. [첨부 원문 비교](/privacy/source/) · [변경·미확정 항목](/reviews/)

## 제1조 목적과 적용 범위

1. 대구가톨릭대학교 RCY(이하 “본회”)의 회원 관리, 동아리 행사, 회계 정산, 활동 확인 및 본회가 직접 결정·관리하는 온라인 업무에 관한 개인정보 처리 기준을 정한다. 학교, 대한적십자사, 봉사실적 등록기관이 독립하여 관리하는 정보는 각 기관의 처리방침과 절차가 적용된다.
2. 전국 RCY Network와 본회의 법적·기술적 운영 주체가 동일한지 여부는 **확정 필요**이다. 본회가 다른 학교의 명부, 플랫폼 전체 계정, 공통 메시지를 모두 통제하는 것처럼 이 방침을 적용하지 않는다. 플랫폼 운영자와 본회의 역할, 업무위탁 또는 제3자 제공 관계를 확인하여 범위를 정한다.
3. 이번 문서 사이트는 규정 열람용이다. 이 사이트 자체에는 로그인, 회원가입 제출, 건강정보 입력, 결제, 채팅, 출석 체크 기능을 추가하지 않았다. 이하 계정·포인트·메신저 관련 항목은 첨부 원문에 기재된 업무이며 **해당 서비스의 실제 운영 여부와 처리 방식을 확인한 후에만 적용**한다.
4. 본 문서의 절차는 정식 시행을 위해 제안하는 기준이지, 이미 구축·이행된 보안 조치나 적법성을 인증하는 문구가 아니다.

## 제2조 처리의 근거와 최소 수집

1. 각 업무의 처리 목적, 실제 필요한 항목, 처리 근거, 보유기간, 접근 담당자를 먼저 정한다. 동의에 근거하는 업무에서는 수집 전에 목적·항목·기간·거부권과 구체적인 불이익을 안내한다. 동의 외 근거를 적용할 때는 해당 법령과 충족 사실을 기록한다. 모든 개인정보 처리가 언제나 동의를 근거로 해야 한다는 뜻은 아니다. [법령 기준](/references/#law-consent)
2. 회원가입, 건강정보, 제3자 제공, 선택적 사진 공개, 국외이전 동의는 필요한 범위에서 구분한다. 약관 동의나 규정 열람 사실을 선택적 개인정보 동의로 간주하지 않는다. 선택 동의 거부만으로 일반적인 동아리 활동에 불이익을 주지 않는 것을 원칙으로 한다.
3. 주민등록번호, 신분증 사본, 성적표, 학교·봉사포털의 비밀번호를 일반 가입·활동 업무의 편의를 위해 요구하지 않는다. 특정 법정 업무에 추가 정보가 필요하면 별도 근거와 안전한 직접 제출 방법을 검토한다.
4. 학번·학과·학년·휴대전화·이메일은 원문상 기본 항목이지만, 동일 목적에 연락수단이 중복되는지 확인한다. 생년월일·성별은 이번 자료의 일반 회원 수집표에 필수로 명시되어 있지 않으므로 **자동으로 필수 항목에 추가하지 않는다**. 적십자 등록 등 별도 업무에서 필요한 항목은 그 업무의 수집·제공 절차로 분리한다.
5. 비상연락처가 다른 사람의 연락처이면 해당 사람의 정보라는 점을 고려한다. 실제 필요성이 없는 행사에서는 수집하지 않고, 수집하는 경우 연락 대상자의 인지·동의 등 적정한 처리 근거와 대체 방법을 확인한다.

처리 근거가 없는 정보를 단순히 표에 기재했다는 이유로 보유하지 않는다. 원문의 “회계 시트·증빙 2년 보존”은 내부 회계 규칙이며 모든 개인정보를 2년 보유할 법정 근거를 자동으로 만드는 것은 아니다. 필요 없는 계좌·연락처는 삭제 또는 가림 처리하고, 식별정보가 남아야 하는 기록은 그 목적·근거·기간을 별도로 확정한다.

## 제4조 민감정보와 미성년자의 정보

1. 건강정보는 일반 회원가입 동의와 분리하여 목적·항목·기간·거부권을 명시한 별도 동의를 받거나 적용 가능한 법령상 근거를 확인한다. “안전 관리”라는 말만으로 전체 병력이나 진단서를 요구하지 않는다. [법 제23조](/references/#law-consent)
2. 접근자는 해당 행사 안전 담당자 등 필요한 사람으로 제한한다. 건강정보를 참가자 단체 채팅방, 공개 명단, 일반 회의록에 적지 않는다. 행사 종료 시 즉시 파기하는 원문 기준을 적용한다. 별도 사고 기록이 필요한 경우도 건강정보 전체를 자동 보존하지 않는다.
3. 만 14세 미만 아동의 개인정보를 동의를 근거로 처리하는 업무를 도입하는 경우, 법정대리인 동의와 확인 절차를 먼저 마련한다. 현재의 대학 동아리 회원관리 범위에 없는 아동 정보를 미리 수집하지 않는다.

## 제5조 개인정보의 제3자 제공

1. 수령 기관이 자신의 목적을 위하여 개인정보를 처리하는 경우에는 업무위탁과 구분한다. 동의에 근거한 제공은 **수령 기관별로** 제공받는 자, 목적, 항목, 보유·이용 기간, 거부권과 불이익을 고지한 후 별도 동의를 받는다. 법령이 허용하는 별도 근거로 제공할 경우에도 해당 근거와 제공 범위를 기록한다.
2. 다음은 원문에 기재된 제공 업무이다. “관할 지사”, “기관 규정” 같은 표현만 남긴 채 실제 동의서를 사용하지 말고 정확한 기관명·구체적인 기간 또는 명확한 종료 기준을 확인한다.

| 원문상 수령 기관 | 목적 | 원문상 제공 항목 | 미확정 정보 |
| --- | --- | --- | --- |
| 대한적십자사 관할 지사 | RCY 단원 등록·관리 | 성명·생년월일·학교·연락처 | 정확한 지사명·제공 경로·수령 기관의 보유기간·필수성 |
| 1365 자원봉사포털 운영기관 | 봉사시간 등록·인정 | 성명·생년월일·봉사활동 내역 | 실제 실적 등록 기관, 식별 방식, 보유기간 |
| VMS 운영기관 | 봉사시간 등록·인정 | 성명·생년월일·봉사활동 내역 | 실제 실적 등록 기관, 식별 방식, 보유기간 |

3. 제공 거부 시 해당 등록·인정 절차에 생기는 제한만 구체적으로 설명한다. 처리 근거 없이 다른 회원 자격까지 제한하지 않는다. 적십자 전산의 정보 삭제는 본회 명부 삭제와 구분하여 안내하고, 본인 요청 시 해당 기관의 권리 행사 절차를 지원한다.
4. 제공 기록에는 날짜, 기관, 목적·근거, 항목, 제공 담당자와 최소한의 식별 정보를 남긴다. 수령 기관이 요구하지 않은 명부 전체나 건강정보를 함께 보내지 않는다.

## 제6조 개인정보 처리업무 위탁

1. 본회를 대신하여 접수·저장·문자 발송 등 업무를 수행하는 서비스가 있다면 수탁자와 위탁 업무를 확인한다. 문서화된 계약, 목적 외 처리 금지, 안전조치, 재위탁 통제, 감독, 종료 시 반환·삭제 및 사고 통지 절차를 마련한다. [법 제26조](/references/#law-processor)
2. 원문은 Google LLC의 폼·스프레드시트·드라이브 사용을 언급한다. 다만 실제 계정 유형, 계약상 법인, 저장·지원 위치, 재위탁자는 첨부 자료만으로 확인되지 않는다. 다음 표를 실제 계약에 맞춰 확정한다.

| 사용 도구·업무 | 원문·사이트에서 확인되는 범위 | 계약·현황 확인 항목 |
| --- | --- | --- |
| Google Forms / Sheets / Drive | 원문에 신청·명부·문서 보관 도구로 기재 | 실제 수탁 법인·위탁 업무·재위탁·계약·삭제 설정·국외이전 |
| RCY Network 운영 인프라 | 원문에 계정·활동 서비스 기재 | 본회와 플랫폼 운영자의 관계 및 실제 인증·DB·저장·메시지 업체 |
| GitHub Pages 문서 호스팅 | 이 문서 사이트의 배포 방식 | 접속정보 처리의 주체·계약상 관계·해외 처리 여부 |

3. 목록에 있다고 개인정보가 해당 업체에 실제 이전되었다고 단정하지 않는다. 사용하지 않는 업무는 정식 방침에서 삭제한다. 수탁자·업무 변경 시 방침을 갱신하고 필요한 고지·계약 절차를 진행한다.

<h2 id="overseas">제7조 국외이전 및 국외 서비스</h2>

해외 사업자 서비스를 사용한다는 설명만으로 국외이전 요건을 충족하는 것은 아니다. 제공·처리위탁·보관·해외 조회 가능 여부를 구분하고 법 제28조의8상 적용 근거를 확인한다. 동의를 근거로 하는 경우에는 아래 사항을 구체화하여 **별도 동의**를 받는다. 동의 외 근거를 적용하는 경우에도 해당 요건 및 공개·보호조치를 확인한다. [개인정보 포털 국외이전 안내](/references/#law-overseas)

| 확정할 항목 | 기재할 실제 정보 |
| --- | --- |
| 이전받는 자 | 계약상 법인명, 담당 연락처, 재위탁 관계 |
| 이전 국가 | 실제 저장·처리·지원 접근 국가; 본사 국가만으로 추정하지 않음 |
| 이전 개인정보 | 업무별로 이전되는 구체적인 항목 |
| 이전 시기·방법 | 신청 제출 시, 저장·백업 시, 관리자 접근 시 등 실제 시점과 전송 방식 |
| 이용 목적 | 신청 접수, 보관, 인증 등 위탁 범위에 맞는 목적 |

| 보호조치 | 접근 통제, 계약, 암호화, 사고 통지 및 권리 행사 지원 |

**모든 항목은 현재 확정 필요이다.** Google 또는 특정 클라우드의 국가·보유기간을 임의로 기재하지 않는다. 대체 접수 이메일도 같은 해외 도구를 사용하면 국외이전 회피 대안이 아닐 수 있으므로, 실제 대체 경로를 검증한다. 이 미완성 표 자체를 국외이전 동의서로 사용하지 않는다.

## 제8조 보유기간 종료와 파기

1. 보유기간 경과, 목적 달성, 적법한 삭제·철회 요청 등으로 정보가 불필요해지면 지체 없이 파기한다. **월말까지 보관을 미루지 않는다.** 원문의 월말 절차는 “월 1회 파기 누락 여부 점검”으로 변경하는 것을 제안한다. [법 제21조](/references/#law-destruction)
2. 담당자는 대상과 근거를 확인하고 원본 데이터, 내보낸 파일, 개인 PC·휴대전화 사본, 공유 링크, 휴지통, 첨부파일을 함께 점검한다. 전자 정보는 복구·재생되지 않도록 삭제하고 종이는 파쇄 등으로 폐기한다.
3. 백업 삭제가 즉시 반영되지 않는 시스템은 접근을 차단하고 운영 데이터로 복원하지 않도록 관리한다. 백업 주기·최종 삭제 기한을 실제 계약과 설정에 따라 공개할 수 있도록 확인한다. 복구 작업으로 삭제 정보가 다시 나타나면 삭제 목록을 재적용한다. 무기한 백업 보유를 허용하는 조항으로 사용하지 않는다.
4. 다른 법령에 따른 보존이 필요한 때에는 법령명·조문, 보존 항목·기간을 확인하여 일반 업무 데이터와 분리한다. 분쟁·확인서 대응을 이유로 별도 보유하려면 그 업무 자체의 적법한 처리 근거와 최소 기간을 먼저 확인한다. 내부 규정만으로 개인정보 파기 예외를 만들지 않는다.
5. 파기 기록에는 처리일, 대상 업무, 범위·건수, 방법, 확인자를 남기되 삭제한 개인정보 본문을 다시 복제하지 않는다. 공개 회의록에는 개인을 알아볼 수 없는 처리 건수 등만 기재한다.

<h2 id="rights">제9조 정보주체의 권리와 신청 절차</h2>

1. 정보주체는 자신의 개인정보에 대해 법령에 따른 열람, 정정·삭제, 처리정지, 동의 철회를 요청할 수 있다. 대리인을 통한 행사에는 필요한 범위의 대리 권한을 확인한다. 법령상 전송 요구나 자동화된 결정 관련 권리가 적용되는 경우 해당 요건과 절차를 추가한다.
2. 접수 창구는 제15조의 담당 연락처로 한다. **현재 공개 연락처는 미확정**이므로, 실제 사용하는 연락처를 기재하기 전에는 이 문서를 최종 방침으로 시행하지 않는다. 공개 GitHub Issue에 회원 정보나 신분증을 제출하도록 안내하지 않는다.
3. 요청은 “본인 연락수단 / 대상 업무 / 요청 내용 / 회신 방법”을 중심으로 받는다. 본인 확인은 기존 연락수단 등 최소한의 방법으로 하고, 주민등록번호나 신분증 사본을 일률적으로 요구하지 않는다.
4. 접수 사실을 알리고 담당자를 배정한다. 원문의 **7일 이내 회신**은 내부 처리 목표로 유지하되 모든 권리에 공통된 법정 기한으로 설명하지 않는다. 실제 적용되는 법령상 기한·연기·거절 절차를 우선한다. 연기 시 사유와 예정일, 거절 시 근거와 이의 방법을 통지한다.
5. 정정·삭제 또는 처리정지 요청이 있는 정보는 필요한 조치를 검토하는 동안 부적절한 추가 이용을 막는다. 외부 수령 기관에 대한 정정·삭제 요청이 필요하면 본회의 통제 범위와 해당 기관의 역할을 구분하여 지원한다.
6. 철회로 제한되는 기능은 해당 처리에 의존하는 범위로 설명한다. 이미 적법하게 이루어진 제공이나 상대방이 보유한 사본을 본회가 일괄 삭제할 수 있다고 약속하지 않는다. 다만 본회가 관리하는 데이터·공개물은 요청과 법령에 따라 처리한다.

## 제10조 안전성 확보와 임원 권한

아래는 시행을 위한 **운영·기술 기준 제안**이다. 실제 시스템에 적용하고 검증한 항목만 최종 방침에서 이행 사실로 설명한다.

1. 개인정보 접근은 직무별로 필요한 항목에만 허용한다. 일반 홍보·행사 담당자에게 전체 회원명부와 계좌정보를 동시에 열어 주지 않는다. 권한 부여·변경·회수 이력을 관리한다.
2. 공용 비밀번호 전달보다 개인별 계정과 역할 기반 권한을 우선한다. 관리자에게 다중 인증을 적용하고 복구 수단은 접근 통제하여 보관한다. 퇴임·사임·직무 변경 시 필요 없어진 권한과 공유 링크를 **즉시 회수**하는 기준으로 원문의 “7일 이내”를 보완한다.
3. 비밀번호를 직접 관리하는 시스템은 평문으로 보관하지 않는다. 전송 구간 보호, 적정한 암호화·해시, 관리자 접속기록, 악성코드·취약점 점검, 잠금·접근 통제는 실제 서비스 특성과 관련 안전성 기준에 맞추어 적용한다. 특정 알고리즘·보관기간을 확인 없이 구현된 사실로 기재하지 않는다.
4. 회원명부·서명한 동의서·계좌·건강정보·CCTV 영상은 공개 GitHub 저장소, 공개 문서 링크, 단체 채팅방에 올리지 않는다. 실수로 공개한 경우 단순 삭제만으로 회수된 것으로 보지 않고 사본·이력·노출 범위와 사고 대응을 확인한다.
5. 학기 1회 이상 권한, 공유 범위, 보유기간, 수탁자, 처리대장과 실제 데이터의 일치를 점검하는 내부 기준을 둔다. 위반·누락은 담당자·기한을 정해 보완한다.

## 제11조 문서 사이트의 자동 처리와 저장 기능

1. 이번 문서 사이트의 검색은 이미 열린 문서 카드의 제목·설명을 브라우저 안에서 필터링한다. 별도의 검색어 전송·수집 코드를 넣지 않았다. 광고·방문 분석 SDK와 외부 폰트 요청도 추가하지 않았다.
2. 화면 테마를 선택하면 브라우저의 로컬 저장소에 `dcu-rcy-theme`라는 키로 `light` 또는 `dark` 값을 저장한다. 이 값은 이 사이트 코드가 서버로 전송하지 않는다. 브라우저에서 해당 사이트 데이터를 삭제하면 제거할 수 있으며 저장 차단 시에도 문서 열람은 가능하다.
3. 문서 주소 복사 버튼은 사용자가 누를 때 현재 문서 URL을 클립보드에 쓰는 기능이다. 클립보드의 기존 내용을 읽는 기능은 넣지 않았다. 인쇄는 브라우저 인쇄 기능을 사용한다.
4. 정적 사이트라고 호스팅 사업자의 접속정보 처리가 없다는 뜻은 아니다. GitHub 등 실제 호스팅·전송 사업자의 IP 등 기술 정보 처리와 적용 방침은 계약·환경별로 확인해야 한다. 본회가 확인하지 못한 서버 로그의 항목·보유기간을 “없음”으로 단정하지 않는다. [GitHub 공식 개인정보 안내](/references/#github-privacy)

## 제12조 사진·영상과 CCTV

행사 기록 촬영과 공개 홍보는 [촬영·초상 이용 동의서](/media/)에서 목적·매체·기간·철회를 구분한다. 동아리방 보안 CCTV의 설치·관리·열람은 [CCTV 운영·관리 방침](/cctv/)에서 별도로 정한다. 홍보 촬영 동의를 CCTV의 포괄적 설치 근거로 사용하지 않으며, CCTV 영상을 홍보물로 전용하지 않는다.

## 제13조 통계·자동화된 결정과 AI 이용

이번 문서 사이트에는 자동 선발·징계, 얼굴 인식, 광고 프로파일링, 생성형 AI로 개인정보를 전송하는 기능을 추가하지 않았다. 이는 외부 RCY Network 전체 시스템의 기능 확인 결과를 뜻하지 않는다. 향후 해당 처리를 도입할 때는 목적·필요성·근거·수탁 관계·국외이전·정보주체 권리와 안전조치를 먼저 검토한다. 회원명부나 비공개 메시지를 일반 AI 서비스의 입력이나 모델 학습용으로 임의 전송하지 않는다. 개인을 알아볼 수 있는 작은 집단의 통계도 공개 전 재식별 위험을 확인한다.

## 제14조 유출 등 사고 대응

1. 분실, 무단 접근, 오발송, 공개 링크 노출 등 사고를 인지하면 담당자에게 즉시 알리고 추가 접근·전파를 차단한다. 사실 확인과 증거 보존을 병행하되, 추가 피해를 막는 조치를 늦추지 않는다.
2. 정보주체 통지와 감독기관 신고는 서로 구분한다. 실제 유출 등을 알게 된 경우 법령상 통지는 원칙적으로 **72시간 이내** 진행하고, 확인되지 않은 세부 사항이 있으면 확인된 내용과 필요한 대응 정보를 우선 알린 뒤 추가 확인 사항을 보완한다. 법령이 정한 예외는 해당 요건과 사유를 기록하여 적용한다.
3. 1천 명 이상, 민감정보·고유식별정보, 외부의 불법 접근으로 발생한 유출 등 시행령상 신고 대상 여부를 별도로 확인한다. “동아리 인원이 적다”는 이유로 신고 의무가 없다고 단정하지 않는다.
4. 2026년 9월 11일 시행 법령상 통지 대상에 해당하는 **유출 등의 가능성**도 실제 유출 확인 전이라는 이유만으로 통지 검토에서 제외하지 않는다. 법령상 요건·기산점·방법에 따라 판단하고, 실제 유출이 없음을 확인한 경우 등 후속 통지도 이행한다. [시행령 제39조·제39조의3·제40조](/references/#law-breach)
5. 통지·신고 시 사실과 추정을 구분하고, 필요한 개인정보만 포함한다. 사고 조사 결과, 조치·통지 시각, 재발 방지 담당자와 기한을 제한된 내부 기록으로 남긴다.
